## Game Analysis: RAID REALMS v7

**Genre:** Browser-basiertes Deckbuilder-/Kartenspiel-Duell (Single-File HTML/CSS/JS, ~1500 Zeilen).

### Kern-Konzept
- 2-Spieler-Duell (PvP oder vs KI). Ziel: HP des Gegners auf 0 bringen.
- Jeder Spieler wählt eine **Rasse** (10 Rassen), die ein eigenes Startdeck und ein Passiv-Talent liefert.
- Spieler starten mit 60 HP (Vampir: 50 HP), ziehen jede Runde auf 5 Karten.

### Rassen & Passiv-Effekte
| Rasse | Passiv |
|-------|--------|
| Mensch | +1 Gold/Runde bei ≥5 Gold |
| Ork | +2 Schaden bei <10 HP |
| Elf | Zauberketten-Bonus: +2/+4/+6 |
| Untoter | 50% Chance: tote Einheiten kommen als Skelett zurück |
| Drache | Gold verfällt nicht, akkumuliert |
| Zwerg | 1×/Runde: Karte upgraden |
| Fee | 25% Echo – Karte wird 2× gespielt |
| Dämon | 5 HP opfern = +8 Gold; <8 HP: +5 Schaden |
| Werwolf | +1 Schaden pro eigene Einheit (max +4) |
| Vampir | Jeder Schaden heilt 1 HP; Start: 50 HP |

### Kartentypen
- **Zauber (spell):** Sofortwirkung (Schaden, Effekte)
- **Einheit (unit):** Geht aufs Feld (max 7 Slots), hat ATK/HP, kann angreifen
- **Gebäude (building):** Passive Effekte jede Runde (Gold, Heilung, Schaden, Spawns)
- **Ressource (resource):** Gold, Heilung, Karten ziehen

### Keywords
- **Taunt** – muss zuerst angegriffen werden
- **Charge** – kann sofort angreifen (kein Summoning Sickness)
- **Lifesteal** – Schaden heilt Angreifer
- **Fortify** – Gebäude blockiert Direktangriffe auf den Spieler

### Rundenablauf (2 Phasen implementiert)
1. **Haupt-Phase:** Karten ausspielen + Karten kaufen vom Markt
2. **Kampf-Phase:** Einheiten → Ziel wählen (Einheit, Gebäude, oder Spieler direkt)

### Markt-System
- 6 zufällige Karten (Tier 1–3, Kosten 2/5/10 Gold)
- Reroll für 2 Gold
- Gekaufte Karten gehen in den Ablagestapel (Deckbuilder-Mechanik)

### Upgrade-System
- Gebäude upgraden: 3 Gold → verbesserte Stats
- Handkarten upgraden: 2 Gold → +1 auf Schadenwerte/Stats
- Zwerge: 1×/Runde kostenloses Hand-Upgrade

### KI
- Simpel: spielt alle Karten, kauft teuerste leistbare Karte, greift Taunt-Ziele bevorzugt an

### Technik
- Komplett einzelne HTML-Datei, keine Dependencies
- Pixel-Art-Sprite-System: 16×16 Sprites in JS-Arrays, gerendert als SVG
- Web Audio API für Sound-Effekte (Synthesizer-basiert)
- Responsive Grid-Layout, Dark Fantasy-Theme

### Kartendatenbank
- ~70 einzigartige Karten (DB-Objekt), verteilt auf Tier 0 (Starter), Tier 1 (2 Gold), Tier 2 (5 Gold), Tier 3 (10 Gold)

## Major Overhaul: v7 → v8

- 2026-02-18T00:05:00 — Began total overhaul implementing all 5 pillars.
- Created `raid-realms-v8.html` (preserves v7 as backup).

### Pillar 1: Pro Split-Screen Layout
- **Complete HTML restructure**: Hearthstone-inspired vertical split.
  - **Top**: Enemy bar (avatar + HP + gold + deck count + card backs for hand)
  - **Upper board**: Enemy units + buildings
  - **Center zone**: Turn badge, phase badge, End Phase button, market strip, reroll, upgrade button
  - **Lower board**: Player units + buildings
  - **Hand zone**: Player's cards with fan spread
  - **Bottom**: Player bar (avatar + HP + gold + deck count)
- Stats (HP, Gold) are physically attached to character avatars.
- Game log moved to fixed overlay (bottom-left, toggleable).

### Pillar 2: Pay-to-Play Economy (Gold = Mana)
- `playCard()` now checks `player.gold >= card.cost` before playing.
  - If insufficient gold: card shakes (CSS animation), SFX error plays, action cancelled.
  - If sufficient: gold deducted, card played with fly-up animation.
- All Tier 0 (starter) cards: cost 0 (free) — no soft-lock possible.
- Tier 1: 2 gold, Tier 2: 5 gold, Tier 3: 10 gold to play from hand.
- `startTurn()`: +2 Gold base income automatically.
- Market buying also costs gold (separate expenditure from playing).
- Unaffordable cards in hand are visually dimmed (opacity + desaturation).
- Use-it-or-lose-it: hand discarded at end of turn, fresh draw next turn (kept from v7).

### Pillar 3: Juice & Physics
- **Screen shake**: `screenShake()` / `screenShake(true)` when damage >4. CSS keyframe animation with rotation.
- **Damage vignette**: Red edge flash (`box-shadow inset`) when player takes direct damage.
- **Positioned particles**: `positionedBurst(el)` spawns 14 particles at the exact card's DOM position when a unit/building dies.
- **Card hover**: Hand cards lift 28px + scale 1.18× on hover with cubic-bezier easing.
- **Card fan spread**: Cards in hand have slight rotation + vertical offset for a natural fan feel.
- **Card play animation**: `cardFlyUp` keyframe — card flies upward and fades when played.
- **Card shake error**: `cardShake` keyframe + red border when trying to play unaffordable card.
- **Turn banner**: "DEIN ZUG" / "GEGNER" banner pops in and fades (scale + opacity animation).
- **Summoning sickness indicator**: 💤 emoji overlay on units that can't attack yet.

### Pillar 4: Truth in UI (Dynamic Numbers)
- New function `getActualValues(card, player)` calculates real damage/gold considering:
  - Card upgrades
  - Elf spell chain bonus
  - Orc low-HP bonus (+2)
  - Demon low-HP bonus (+5)
  - Werewolf unit-count bonus
  - Damage buff from Whetstone
- `getDynamicEffectText()` renders card text with `<span class="val-buffed">` highlighting when values are boosted.
- Buffed values glow green (`#50ff80`) with text-shadow.

### Pillar 5: Smarter, Faster AI
- New `aiScoreTarget(target, opp, atk)` scoring function:
  - Gold-generating targets: goldPerTurn × 8
  - Healing targets: healPerTurn × 7
  - Mass healers: healAllPerTurn × 10
  - Damage buildings: damagePerTurn × 5
  - Spawners: +15
  - Fortify buildings: +12
  - Easy kills (health ≤ attack): +10
  - Face: base 10, lethal = 999, penalized if board has value targets
- AI plays cards sorted by cost (free first, then resources for gold, then damage).
- AI combat selects best-scored target per unit.
- **All setTimeout delays reduced ~50%**: 300ms between card plays (was ~600), 350ms between attacks, 400ms phase transitions.
